# アカウント準備手順（フェーズ1）

取得した値は `案件５/.env.local` の該当行に貼り付ける。チャットには貼らない。

| # | サービス | 所要時間 | 取得する値 |
|---|---|---|---|
| 1 | Supabase | 10分 | `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` |
| 2 | LINE | 15分 | `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_MANAGER_USER_ID` |
| 3 | Slack | 15分 | `SLACK_BOT_TOKEN` / `SLACK_CHANNEL_*`（5つ） |
| 4 | Gmail | 5分 | なし（GASの設定はフェーズ2で行う） |

`ANTHROPIC_API_KEY`・`MAIL_INGEST_SECRET`・`CRON_SECRET` は設定済み。

---

## 1. Supabase

1. https://supabase.com/dashboard →「New project」
   - Name: `問い合わせ集約`（任意）／Region: **Northeast Asia (Tokyo)**
2. 作成後、左メニュー「SQL Editor」→ `supabase/schema.sql` の中身を貼り付けて「Run」
   - 「Success. No rows returned」と出ればOK
3. 「Project Settings」→「API Keys」と「Data API」から値をコピー
   - Project URL（画面によっては「API URL」と表示）→ `SUPABASE_URL`。`https://xxxx.supabase.co` の形で、末尾に `/rest/v1` などは付けない
   - `service_role`（secret）キー → `SUPABASE_SERVICE_ROLE_KEY`

## 2. LINE（お客様の窓口役 ＋ 部長への通知役）

1. https://manager.line.biz/ で LINE公式アカウントを新規作成（名前例：`〇〇不動産 問い合わせ（テスト）`）
2. 作成したアカウントの「設定」→「Messaging API」→「Messaging APIを利用する」→ プロバイダーを選択（新規作成で可）
3. 「設定」→「応答設定」
   - **Webhook：オン**
   - **応答メッセージ：オフ**（自動返信が混ざらないように）
   - チャット：オンのままでよい（ヒアリング未回答の「チャット運用との両立」をここで確認できる）
4. https://developers.line.biz/console/ → 作成したチャネルを開く
   - 「チャネル基本設定」→ **チャネルシークレット** → `LINE_CHANNEL_SECRET`
   - 同じ画面の下の方 → **あなたのユーザーID**（`U` で始まる）→ `LINE_MANAGER_USER_ID`（あなたが部長役）
   - 「Messaging API設定」→ **チャネルアクセストークン（長期）**「発行」→ `LINE_CHANNEL_ACCESS_TOKEN`
   - Webhook URL はフェーズ2で設定する（公開URLが必要なため）
5. 同じ画面のQRコードから、**自分の個人LINEで友だち追加**する
   - 友だちになっていないと、緊急通知（プッシュ）が届かない

## 3. Slack

1. テスト用ワークスペースを用意する（既存のものでも可）
2. チャンネルを5つ作成する
   - `#問合せ-賃貸` `#問合せ-売買` `#問合せ-内見` `#問合せ-クレーム` `#問合せ-その他`
3. https://api.slack.com/apps →「Create New App」→ **「From a manifest」** → ワークスペースを選択 →「YAML」タブに以下を貼り付け →「Next」→「Create」

   ```yaml
   display_information:
     name: inquiry-router
     description: Routes email and LINE inquiries to Slack channels with AI
   features:
     bot_user:
       display_name: inquiry-router
       always_online: true
   oauth_config:
     scopes:
       bot:
         - chat:write
   settings:
     org_deploy_enabled: false
     socket_mode_enabled: false
     is_hosted: false
     token_rotation_enabled: false
   ```

   - 日本語を貼り付けるとマニフェスト画面で文字化けするため、名前は英数字にしている（日本語名にしたい場合は、作成後に「Basic Information」「App Home」で変更する）
   （「Blank app」で作る場合は、作成後に「OAuth & Permissions」→「Bot Token Scopes」に `chat:write` を手で追加する）
4. 作成後の画面で「Install to Workspace」→ 許可
5. 左メニュー「OAuth & Permissions」→ **Bot User OAuth Token**（`xoxb-`）→ `SLACK_BOT_TOKEN`
6. 5つのチャンネルそれぞれで `/invite @inquiry-router` を実行する（招待しないと投稿できない）
7. 各チャンネル名をクリック → 一番下の **チャンネルID**（`C` で始まる）をコピー

| チャンネル | 変数 |
|---|---|
| #問合せ-賃貸 | `SLACK_CHANNEL_RENTAL` |
| #問合せ-売買 | `SLACK_CHANNEL_SALES` |
| #問合せ-内見 | `SLACK_CHANNEL_VIEWING` |
| #問合せ-クレーム | `SLACK_CHANNEL_COMPLAINT` |
| #問合せ-その他 | `SLACK_CHANNEL_OTHER`（「未分類」もここに投稿） |

## 4. Gmail

1. テスト用の Gmail アカウントを用意する（お客様からのメールを受ける窓口役）
2. 別のアドレスからテストメールを送れるようにしておく
3. GAS の設定（1分ごとの新着確認・署名付き送信）はフェーズ2で行う

## 完了の確認

すべて貼り終えたら Claude Code に「準備できました」と伝える。次のコマンドで、空の値が残っていないか確認できる。

```bash
awk -F= '/^[A-Z]/{print $1, (length($2)>0?"OK":"未設定")}' .env.local
```

`CLAUDE_MODEL` は空のままでよい（空なら `claude-haiku-4-5` を使う）。
